PocketDesk 跨端 AI 工作台规范 v1.0
Sep 26, 2026 · @Lisa Stonego
PocketDesk 由电脑端一个常驻服务（Go 单文件）和手机端一个类微信风格的客户端（Flutter）组成。手机端可以与电脑上的 AI 编程工具对话、查看和编辑工作区文件、双向传输文件。所有数据只经过你自己的设备和网络。
1. 概述
目标
1. 在手机上像发微信一样，向电脑上的 Claude Code、Codex、Pi、DSH（DeepSeek Harness）发送提示词，实时看到回复、工具调用和改动，并在手机上审批敏感操作。
2. 手机与电脑之间双向传输文本、图片和任意格式文件，支持断点续传、自动恢复和多路加速。
3. 在手机上浏览、查看、编辑电脑上指定工作区里的文件。.md 文件点击后由电脑自动转成 PDF 并缓存，手机直接阅读 PDF。
4. 提供一个原始终端作为兜底，可以在手机上执行任意命令。

2. 总体架构与技术选型
客户端用 Flutter 一套代码覆盖 Android 与 iOS；电脑端用 Go 一套代码交叉编译出 macOS 与 Windows 版本。两端只走标准协议：HTTPS、WebSocket、tus 断点上传、HTTP Range 下载。

为什么选 Flutter 而不是各自原生
• 一套代码、一套 UI，类微信界面在 Android 和 iOS 上完全一致，维护成本减半。
• 生态成熟：后台传输、PDF 查看、终端渲染都有使用原生能力的插件，不需要内嵌大型库。
• 代价是体积：Flutter 引擎会占用约 4–5MB。原先 Kotlin 原生版本的 2–3MB 目标调整为：Android 单架构 APK ≤ 10MB，iOS 下载体积 ≤ 15MB。如果日后体积比跨平台更重要，可以把 Android 端单独改回原生 Kotlin，服务端和协议都不用改。

3.4 消息页（会话列表）
• 每行显示：头像、会话名、最后一条消息摘要、时间、状态。
• 状态标识：执行中显示转圈；等待审批显示红色「待确认」；出错显示红色感叹号；未读显示红色数字角标。
• 左滑操作：置顶、标为已读、删除（只删手机上的记录，电脑上的 Agent 会话保留）。
• 右上角「+」弹出菜单：新建 Claude Code 会话、新建 Codex 会话、新建 Pi 会话、新建 DSH 会话、新建终端、扫一扫（配对）。
• 顶部搜索框：搜索会话名和消息内容。
3.5 聊天页
• 顶栏：返回、会话名（下方小字显示工作目录和模型）、右上角「···」进入会话设置。
• 输入栏（从左到右）：语音/键盘切换、文本输入框、「/」指令按钮、「+」扩展面板按钮；输入文字后「+」变成绿色「发送」。
• 语音输入：按住说话，调用系统语音识别转成文字，松开前可以上滑取消，识别结果先放进输入框，确认后再发送。
• 「+」扩展面板（两行宫格）：相册、拍摄、文件、工作区文件、快捷短语、切换模型、打断、终端。
• 长按气泡菜单：复制、引用回复、多选、转发到其他会话、存为 md 文件、删除。
• 消息类型：文本（Markdown 渲染）、图片、文件卡片、工具调用卡片（默认折叠）、审批卡片、改动卡片（文件列表 + diff）、系统提示（灰色居中小字，如「会话已恢复」）。
• 新消息在底部，上滑加载更早的消息；不在底部时出现「↓ N 条新消息」浮标。
3.6 文件页、传输页、我
• 文件页：类似文件管理器的列表，每行显示图标、文件名、大小、修改时间；日期文件夹默认按时间升序。顶部有面包屑路径，可以按名称、时间、大小排序。
• 传输页：分「进行中 / 已完成 / 收件箱」三个分段。进行中的每项显示进度条、速度、并行路数、剩余时间，可暂停、继续、取消。
• 我：电脑卡片（名称、在线状态、延迟、连接方式局域网或 Tailscale）、配对新电脑、传输设置、安全设置、外观、日志导出、关于。

4.3 会话状态机
stateDiagram-v2
  [*] --> 空闲
  空闲 --> 执行中: 发送消息
  执行中 --> 待审批: approval.request
  待审批 --> 执行中: 允许 / 拒绝
  待审批 --> 执行中: 10 分钟未处理，按拒绝处理
  执行中 --> 空闲: 本轮完成
  执行中 --> 已打断: 用户点「打断」
  已打断 --> 空闲
  执行中 --> 出错: 进程异常退出
  出错 --> 空闲: 重试或自动恢复
• 执行中又发了新消息：默认进入排队，本轮结束后自动发送，气泡旁显示「排队中」，不会打断正在执行的任务。
• 打断：服务端向 Agent 发送中止指令（Pi 的 abort、ACP 的取消请求）；没有中止指令的，向进程发送中断信号（macOS 为 SIGINT，Windows 为 Ctrl+Break 事件）。
• 进程意外退出：自动用保存的会话 ID 重启并恢复，插入系统提示「会话已恢复」；连续失败 3 次则停止并提示出错。

4.5 附件、审批与改动
• 发送附件：图片和文件先走断点上传（见第 6 节），存到当前工作目录下的 .pocketdesk/inbox/YYYYMMDD/，再把相对路径附在提示词后面。支持图片输入的 Agent 会直接读取图片。
• 审批卡片：显示操作类型、完整命令或文件路径，按钮为「允许」「拒绝」「本会话总是允许此类操作」。超过 10 分钟未处理按拒绝处理，避免任务无限挂起。
• 改动卡片：每轮结束后，工作目录是 git 仓库的，用 git diff --stat 生成改动清单；不是 git 仓库的，根据本轮工具调用事件里的写文件记录生成。点开单个文件看 diff；.md 文件可以直接以 PDF 方式阅读。
4.6 离线与通知
• 任务在电脑上运行，与手机是否在线无关。手机重连后，按最后收到的 seq 补拉缺失的事件。
• App 在前台时通过 WebSocket 实时接收。
• App 在后台时的通知：
    ◦ Android：可选接入 FCM（部分国内机型收不到），或使用自建或公共的 ntfy 推送。
    ◦ iOS：后台通知必须经过苹果 APNs。v1 使用 ntfy 或 Bark 这类已接入 APNs 的推送 App 转发，不需要自己申请推送证书。
• 通知内容只写「CC 会话需要审批」「CX 会话已完成」，不包含代码或提示词正文。
4.7 文件传输助手
一个特殊会话，行为与微信的「文件传输助手」相同：发文字、图片、文件，直接存到电脑的默认收件目录；电脑发来的文件也会出现在这里。本质上是第 6 节文件互传的聊天化入口。
5. 终端模式
终端是兜底入口，可以在手机上运行任意命令，也可以直接打开任一 Agent 的原生交互界面。终端会话由电脑端持有，手机断线不会结束会话，重连后画面原样恢复。
实现
• 电脑端为每个终端会话创建一个伪终端：macOS 用 PTY，默认 shell 为用户的登录 shell（通常是 zsh）；Windows 用 ConPTY，默认 PowerShell 7，没有则用 Windows PowerShell。
• 不依赖 tmux，保证 Windows 和 macOS 行为一致。服务端自己保留最近 10,000 行输出作为回滚缓冲，手机重连时先回放缓冲，再接实时输出。
• 手机与电脑之间用 WebSocket 传输原始字节流；手机窗口大小变化时同步通知电脑调整终端尺寸。
• 手机端用纯 Dart 的 xterm 组件渲染，支持 256 色、真彩色、鼠标和滚动。
手机端交互
• 键盘上方有一行快捷键栏：Esc、Tab、Ctrl、Alt、↑ ↓ ← →、Home、End、PgUp、PgDn、|、~、/。Ctrl 和 Alt 为粘滞键，点一下后对下一个按键生效。
• 双指缩放调整字号；长按进入选择模式复制文本；粘贴走系统剪贴板。
• 会话列表里终端会话显示为「>_」头像，摘要为最后一行输出。
• 预设「快捷启动」：一键在指定工作区打开 claude、codex、pi、dsh 的原生交互界面，或自定义命令。
限制与安全
• 终端会话的起始目录限制在已授权的工作区内，但 shell 本身可以访问整台电脑。因此终端功能默认关闭，需要在电脑端设置中手动开启，并且每次进入都要生物识别验证。
• 空闲 24 小时的终端会话自动结束，可配置。
6. 文件互传
手机到电脑用 tus 协议断点上传，电脑到手机用 HTTP Range 断点下载。两个方向都支持多文件并发、大文件分段并行、自动恢复和整文件 SHA-256 校验，命名规则完全一致。
6.1 命名与目录规则（双向通用）
1. 文件放进按日期命名的子文件夹 YYYYMMDD/。日期取传输任务创建时的本地时间，续传跨天也不会换文件夹。
2. 有文件名的，保留原文件名。
3. 没有文件名的（分享的纯文本、剪贴板图片、无名数据流），命名为 YYYYMMDD-HHmmss-SSS.扩展名。扩展名根据 MIME 类型推断，纯文本为 .txt。按文件名排序即按时间升序。
4. 重名时加后缀：report.pdf → report-1.pdf → report-2.pdf。
5. 最终文件名在传输完成时确定：先写入临时文件，完成后以「不存在才创建」的原子方式落盘，冲突则序号加一重试。并发传输不会互相覆盖，续传过程中名字不变。
6. 文件名中的非法字符（Windows 的 \ / : * ? " < > | 及保留名如 CON）替换为 _，保证两个系统都能存。

6.2 手机 → 电脑
入口：系统分享菜单（Android 分享目标、iOS 分享扩展）、App 内选择文件或相册、聊天附件、文件传输助手。iOS 分享扩展通过 App Group 共享目录把文件交给主 App 排队。
流程
1. 选中的文件先登记到本地传输队列（SQLite），记录来源、大小、文件指纹（大小 + 修改时间 + 首尾各 1MB 的哈希）、状态。
2. 来源权限是临时的（分享传入的文件），先复制到 App 缓存目录；Android 用 ACTION_OPEN_DOCUMENT 选的文件改为申请持久化读取权限，不复制。
3. 向电脑发起 tus 创建请求，获得上传地址，写入队列。
4. 按块 PATCH 上传，默认块大小 8MB，弱网自动降到 1MB，每块带 SHA-256 校验头。
5. 完成后校验整文件 SHA-256，电脑端按 6.1 的规则落盘，并返回最终文件名。
后台执行
• Android 14 及以上：用户发起的数据传输任务（user-initiated data transfer job），系统不会中途终止。
• Android 13 及以下：WorkManager 加前台服务，通知栏显示进度。
• iOS：每一块先写成临时文件，交给 URLSession 后台会话上传。App 被挂起甚至被系统结束后，系统仍会继续上传并在完成时唤醒 App。
• 可设置仅 Wi-Fi 传输、低电量暂停。
6.3 多路加速
• 文件级并发：默认同时传 3 个文件，可调 1–6。小于 8MB 的文件走快速通道，不排在大文件后面。
• 单文件分段并行：大于 64MB 的文件切成多段，每段是一个 tus「部分上传」，各自独立续传，全部完成后发一个「拼接」请求合成完整文件（tus concatenation 扩展）。
• 自适应路数：从 2 路开始，每 10 秒测一次总吞吐，提升超过 10% 则加 1 路，最多 6 路；吞吐不增或重试变多则减 1 路。所有文件合计连接数不超过 8。切到移动网络或省电模式时降为单路。
• 上传和下载使用的 HTTP 客户端限定 HTTP/1.1，确保每一路是独立的 TCP 连接。HTTP/2 会把多路复用在一条连接上，丢包时全部卡住，失去加速意义。
6.4 电脑 → 手机
入口
• 把文件放进电脑上的发件目录 ~/PocketDesk/Outbox/，服务端监听到后自动推送。
• macOS：Finder 右键「快速操作 → 发送到手机」（用快捷指令调用命令行 pocketdesk send）。
• Windows：资源管理器右键「发送到 → PocketDesk」（安装时在「发送到」目录放一个快捷方式）。
• 命令行：pocketdesk send <文件...> [--to <设备名>]，方便脚本和 Agent 调用。
• 在手机「文件」页浏览工作区，直接点下载。
流程
1. App 在前台时通过 WebSocket 立即收到通知；在后台时依赖推送（见 4.6）或每 15 分钟一次的后台检查。
2. 下载用 Range 请求续传，带 If-Range: <ETag>：如果电脑上的文件在此期间被修改，服务端返回完整新文件，客户端从头下载。
3. 大文件分段并行下载，每段写入预分配临时文件的对应位置，各自记录进度。
4. 校验 SHA-256 通过后，按 6.1 的规则写入手机的目标目录。
5. 手机确认收到后，电脑端把 Outbox 里的文件移到 Outbox/.sent/YYYYMMDD/，不会重复发送。

7.3 编辑与冲突
• 纯文本：App 内置简单的等宽文本编辑器，支持撤销、查找替换。保存时带上打开时的 ETag（If-Match），电脑端在期间被修改过则返回 412。此时弹窗让用户选择「覆盖」「另存为 原名-1」「放弃我的修改」，并可先查看差异。
• 其他格式：用其他 App 编辑后回到 PocketDesk，App 检测到缓存文件有变化，询问是否传回电脑，同样带 If-Match 防止覆盖。
• 保存方式：电脑端先写临时文件再原子替换，写到一半断网不会损坏原文件。
• 只读工作区中的文件不显示编辑入口。
7.4 Markdown 转 PDF 阅读
流程：点击 .md 文件 → 手机请求转换 → 电脑检查缓存，命中则直接返回，否则转换 → 手机下载 PDF（本地已有相同版本则跳过）→ 在 App 内阅读。
缓存位置：在工作区根目录下按原路径镜像存放。例如 20261001/会议纪要.md 对应 .pocketdesk/cache/pdf/20261001/会议纪要.pdf，旁边存一个同名的 .meta 文件，记录源文件哈希和渲染配置版本。
是否需要重新转换：以下任意一项变化即重新转换：
• md 源文件的 SHA-256；
• md 引用的本地图片的修改时间；
• 渲染配置版本（主题、页面尺寸、字号）。
转换引擎
1. goldmark 把 Markdown 转成 HTML：支持 GFM 表格、任务列表、脚注、代码高亮、KaTeX 数学公式、mermaid 图表、本地图片。
2. 使用内置的阅读样式（中文排版友好，标题层级清晰，代码块自动换行）。
3. 用 chromedp 驱动本机 Chrome 或 Edge 无头打印成 PDF。Windows 自带 Edge，开箱即用；macOS 未安装 Chrome 或 Edge 时，退回使用系统自带 WebKit 生成 PDF（附带一个很小的 Swift 辅助程序）。
4. 页面尺寸为手机阅读优化：宽 110mm，高度按内容分页，正文字号 11pt，页边距 6mm。手机上不用缩放就能看清。设置中可以切换为 A4。
并发与性能
• 同一文件的多个转换请求合并为一次（singleflight），其他请求等待同一结果。
• 常驻一个无头浏览器实例，空闲 5 分钟后关闭，避免每次冷启动。
• 目标：普通文档（≤ 50KB 文本、≤ 10 张图）缓存未命中时 2 秒内出结果，命中时 200 毫秒内返回。
阅读体验
• 上下连续滚动，双指缩放，支持夜间模式（反色显示）。
• 自动记住每个文档的阅读位置，下次打开回到原处。
• 在日期文件夹内阅读时，左右滑动切换到同一文件夹中的上一篇或下一篇（按时间升序）。
• 右上角菜单：刷新（强制重新转换）、以纯文本查看或编辑源文件、分享 PDF、发给 Agent 会话。
8. 连接、配对与安全
这套系统等同于「手机远程控制电脑执行代码」，因此安全要求按最高标准设计：只在局域网或 Tailscale 内可达，扫码配对并固定证书，敏感操作需生物识别和逐条审批。
8.1 连接
• 局域网：电脑端通过 mDNS 广播 _pocketdesk._tcp 服务，手机自动发现，电脑 IP 变化也能找到。
• 外网：两端都安装 Tailscale，手机使用电脑的 Tailscale 地址（100.x.x.x 或 MagicDNS 名称）连接。不需要公网 IP 和端口映射，流量端到端加密。
• 自动切换：手机保存电脑的多个地址，按「局域网 → Tailscale」顺序探测，选延迟最低的可用地址；网络切换后自动重连。
• 电脑端默认只监听局域网和 Tailscale 网卡，绝不监听公网。
8.2 配对
1. 电脑端首次启动时生成自签名证书和设备身份，托盘菜单中「配对新手机」显示二维码。
2. 二维码内容：电脑名称、各个地址、端口、证书 SHA-256 指纹、一次性配对码（5 分钟有效）。
3. 手机扫码后连接电脑，校验证书指纹一致，提交配对码。
4. 电脑端弹窗确认「是否允许 xxx 手机配对」，用户点允许后下发该手机专属的长期令牌。
5. 手机把令牌存入系统安全存储（Android Keystore / iOS 钥匙串），此后每次连接都校验证书指纹（证书固定），防止中间人攻击。

• 地址：wss://<主机>:8443/ws，连接后发送 {"type":"hello","cursors":{"<会话ID>":<最后收到的seq>}}，服务端先补发缺失事件，再推实时事件。
• 服务端推送的消息格式：{"session":"...","seq":123,"type":"msg.delta","data":{...}}，类型见 4.2 节。
• 另有全局事件：transfer.progress（电脑端视角的传输进度）、outbox.new（电脑有新文件要发）、host.status。
• 每 25 秒一次心跳；60 秒没收到心跳即判定断线，客户端按指数退避重连。
9.3 终端通道
• 地址：wss://<主机>:8443/term/{会话ID}，二进制帧传输终端原始字节。
• 控制消息使用文本帧：{"type":"resize","cols":80,"rows":24}。
• 连接后服务端先回放回滚缓冲，再接实时输出。
9.4 版本兼容
• 所有响应都带 X-PD-API: <版本号>。App 启动时读取 /api/host，若电脑端版本过旧，提示升级电脑端，并隐藏不支持的功能。
• 接口只增加字段不删除；需要破坏性变更时使用新路径前缀 /api/v2/，旧接口至少保留一个大版本。

11.3 路径与编码
• 协议中的路径一律用 / 分隔、UTF-8 编码、相对于工作区根目录；电脑端负责转换为本机格式。
• 文件名比较：macOS 文件系统默认不区分大小写，Windows 同样不区分，判断重名时按不区分大小写处理。
• macOS 文件名为 NFD 形式的 Unicode，统一转换为 NFC 后再传给手机，避免中文、日文文件名显示或比较出错。
• 文本文件保留原有换行符（LF 或 CRLF）和编码；无法识别为 UTF-8 的文件以只读方式打开。
